# 应用结构

## 启动与模块边界

`src/main.js` 加载样式并创建应用。`src/app/create-app.js` 是唯一组合根：创建配置、界面状态、运行时状态、存储服务与 DOM 引用，注册模块，再加载原图并渲染首屏。

页面通过事件委托触发 `app/events.js` 中的分发逻辑。导航负责 hash 与返回行为，控制器处理用户意图，领域模块处理到访归档规则，存储模块负责持久化，页面模块生成界面。

`appContext` 按职责分组：

| 成员                                          | 职责                                           |
| --------------------------------------------- | ---------------------------------------------- |
| `config`、`catalog`、`fixtures`               | 配置、内容目录与演示初始数据                   |
| `data`                                        | 可持久化的完整业务状态                         |
| `ui`                                          | 当前页面、筛选、待提交票根、分享选择           |
| `runtime`                                     | 取消令牌、计时器、弹窗状态、演示备份等临时对象 |
| `dom`、`assets`                               | 挂载点与构建后资源地址                         |
| `domain`、`selectors`                         | 数据规则及当前状态查询                         |
| `storage`、`media`                            | 元数据持久化及原图存储                         |
| `navigation`、`claims`、`memories`、`dialogs` | 交互控制器                                     |
| `views`、`render`                             | 页面函数与渲染调度                             |
| `sharing`、`images`、`format`、`feedback`     | 导出、图片、展示工具及反馈                     |

模块工厂只注册函数，业务数据在注册完成后读取。所有模块动态访问 `appContext.data`，因此首次使用演示替换整份数据时，不会有模块继续操作旧对象。

`createApp().destroy()` 会解绑事件、取消待提交操作、关闭弹窗并释放对象 URL。Vite 开发热更新可以调用此生命周期方法。

## 数据模型

```text
data
├─ records[stampId]            已收藏的章、收藏编号、首次领取日期及到访日期
├─ visits[venueId/date]        到访主体：场馆、日期、票根、徽章、照片、感想
├─ tickets[ticketId]           票根元数据、保存状态及已领取章
├─ wanted[]                   想去的场馆
├─ profile.public             对别人公开的部分：章册、足迹、感想与照片
├─ posts[]                    发布到广场的到访：每次到访一条，保存发布时的感想与照片副本
└─ liked[]                    赞过的广场动态
```

其他收藏家与他们在广场上的动态是 `fixtures.collectors`、`fixtures.posts` 中的演示数据，不进入 `data`；榜单、名次、收藏者名录与广场的信息流由 `state/community.js` 在读取时计算。

一条到访可以引用多张票根和多枚章。同一场馆、同一天始终合为一次到访。感想和照片归属于到访，不会因为同馆的另一段参观被覆盖。

`domain/visits.js` 不依赖 DOM。它负责字段规范化、旧数据迁移、关联校验与合并。元数据存储与 IndexedDB 存储位于 `storage/`，原图不会进入 JSON 元数据或网站构建。

第一次读取新版时，可以从旧版键迁移数据。旧版感想归入原参观日期，较早的补录日期保持独立；已经主动清空的新版感想不会被旧备份重新填回。

## 渲染与样式

`views/` 按页面分组，动态个人文本通过统一的 HTML 转义函数写入页面。图标定义保留在 `index.html`，插画通过 ES Module 资源导入交给 Vite 处理。

样式按 `tokens → base → tickets → memories → collectors → map → square` 的顺序导入，保留现有界面的级联关系。修改颜色与字体从 `tokens.css` 开始，票根和到访页面分别在对应样式文件中调整。

### 配色

界面的颜色全部在 `src/styles/tokens.css` 里命名，其余样式文件只引用名字，不直接写色值。

| 分组 | 变量                                                       | 用途                                                           |
| ---- | ---------------------------------------------------------- | -------------------------------------------------------------- |
| 底色 | `--paper` `--wash` `--soft` `--sunken`                     | 页面与卡片；输入框与空位；分区、胶囊与次级按钮；按下与评审底色 |
| 线   | `--line` `--line-strong` `--idle` `--edge` `--edge-strong` | 分隔线；卡片与控件描边；未选中的页点与开关；虚线空位           |
| 文字 | `--faint` `--subtle` `--muted` `--ink`                     | 编号与提示；说明；辅助正文；正文与标题                         |
| 行动 | `--accent`                                                 | 可以点的、被选中的；现在是护照封面的黑                         |
| 印记 | `--owned` `--want` `--like`                                | 已收藏、想去、赞                                               |
| 其他 | `--danger` `--on-fill` `--shadow`                          | 出错；压在色块上的字与图标；投影的颜色                         |

浅底、描边、光晕、投影等（`--accent-soft`、`--accent-line`、`--accent-ink`、`--owned-soft`、`--veil`、`--scrim`、`--shade-1` 到 `--shade-4` 等）由 `color-mix()` 从上面的颜色算出，写在同一个文件的第二段；换掉 `--accent`，它们跟着变。

可以点的文字用 `--link`，默认就是 `--accent`。主色是黑色时它和正文分不开，所以这类文字另外加重一档字重，并带一个图标或在后面跟一个小箭头（规则在 `base.css` 的 `.button.text` 之后）。主题若想让文字链接有自己的颜色，覆盖 `--link` 一项即可。

物件自己的颜色不在其中，留在各自的样式里：章缘与光晕、奖牌、护照封面与册子的纸张、示例票根、旅行卡（预览与 `services/share-card.js` 画出的图片用同一组色值）、地图插画。

加一套主题，是在 `tokens.css` 末尾用同样的名字再写一段，并在 `<html>` 上设置 `data-theme`：

```css
[data-theme='vermilion'] {
  --accent: #b8432f;
}
```

只换主色时写 `--accent` 一项即可；要连中性色一起换（比如暖灰），把底色、线、文字三组一并覆盖。物件的颜色不随主题变化，所以深色主题还需要另行处理册子、票根与旅行卡。

## 构建

网站版使用 Vite 的普通客户端构建，生成带哈希的资源与 `dist/site/index.html`。单文件构建使用同一入口的 IIFE 输出，把代码、CSS 和内联图片嵌入同一份 HTML。

两种构建都从当前源码生成，不依赖历史原型或手工维护的代码拼接清单。`artifacts/` 中的旧版文件只供回看。

## 测试与服务接入

领域规则用 Node.js 原生测试运行，浏览器行为用 Playwright 验证。浏览器测试使用隔离上下文及专用端口；`scripts/test-e2e.mjs` 在进程内管理 Vite 测试服务器，运行结束后主动关闭，避免 Windows shell 子进程清理挂起。

接入真实服务时，优先替换 `storage/` 的本地数据源和 `controllers/claims.js` 中的模拟识别、匹配与领取逻辑；保留 `visits` 的归档关系。客户端的文件指纹只能用于当前演示的重复图片提示，不能承担票根真实性验证。
