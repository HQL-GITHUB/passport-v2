# 应用结构

## 启动与模块边界

`src/main.js` 加载样式并创建应用。`src/app/create-app.js` 是唯一组合根：创建配置、时钟、后端、界面状态、运行时状态与 DOM 引用，注册模块，再通过 `store.load()` 向后端取回目录、社区与护照数据，最后渲染首屏。数据到达之前按钮不响应；等待超过 400 毫秒显示加载提示，失败时显示重试。

页面通过事件委托触发 `app/events.js` 中的分发逻辑：按钮的 `data-action` 对应 `actions/` 中按功能分组的一张动作表；输入框、选择框与开关同理，`data-input`（每次键入）或 `data-change`（值改变）对应同一批文件里的字段表。动作只处理界面状态与跳转；需要改动数据时调用控制器，控制器通过 `store` 把命令发给后端。导航负责 hash 与返回行为，领域模块是不依赖 DOM 的纯规则，页面模块生成界面。文字转义、图标、日期与编号的写法是 `lib/format.js` 里的纯函数，页面模块直接导入。

有哪些页面写在 `app/screens.js` 的一张表里，一行就是一个页面与别的页面不同的全部：

| 字段                     | 含义                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| `view`、`actions`        | 渲染页面的函数，以及渲染页面操作区（`#page-actions`）按钮的函数    |
| `about`                  | 地址里带的 id 是什么：场馆、章、到访、收藏家或广场动态             |
| `root`                   | 底部导航上的页面：页头显示品牌而不是返回                           |
| `caption`、`title`       | 页头的标题与浏览器标签的标题，可以是函数                           |
| `tools`                  | 渲染页头右侧按钮的函数                                             |
| `parent`                 | 直接打开、身后没有历史时，返回去哪里：页面名，或自己完成跳转的函数 |
| `guard`                  | 页面要展示的东西不存在时，由哪个页面代替                           |
| `place`                  | 除了页面的主体之外，滚动位置还跟着哪些界面状态                     |
| `claiming`、`keepsDraft` | 是否属于正在领取的流程；离开它时是否保留正在录入的票根             |

导航、页头与页面操作区都从这张表读取。增加页面时在这张表里加一行，并写出对应的页面函数。

页面讲的是哪一种东西（`about`）会带来一串不同：地址怎么写、怎么读，滚动位置跟着谁，当前的场馆、章与到访是哪一个。这些写在 `app/subjects.js` 的另一张表里，场馆、章、到访、收藏家、广场动态各一行，外加不讲任何东西的页面用的 `none`：

| 字段                      | 含义                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| `of`                      | 页面状态里哪一项指的是它；滚动位置按它保存                        |
| `read`                    | 从地址里读出它（收藏家、广场动态、到访的日期）                    |
| `take`                    | 带着某个 id 进入页面时，页面记下的场馆或章（`ui.selected`）是什么 |
| `address`                 | 地址里页面名之后的部分怎么写                                      |
| `venue`、`stamp`、`visit` | 当前的场馆、章与到访；`selectors` 里的同名查询就是从这里取的      |

导航与查询只调用当前页面那一行，自己不再区分种类。增加一种主体时在这张表里加一行。

弹窗同理：`controllers/dialogs.js` 里有一张弹窗表，每种弹窗一行，写明由哪个页面函数给出标题、内容与初始状态，以及自己的样式类、打开后的焦点和初始化。弹窗的内容写在对应功能的 `views/` 文件里。

`appContext` 按职责分组：

| 成员                                                      | 职责                                                |
| --------------------------------------------------------- | --------------------------------------------------- |
| `config`、`clock`                                         | 配置；「今天」的唯一来源（演示中固定为 `demoDate`） |
| `api`                                                     | 后端。当前是 `api/local/` 的本机实现                |
| `store`                                                   | 加载数据、发送命令，并把后端的回答写回 `data`       |
| `catalog`、`community`、`data`                            | 后端返回的场馆与章、其他收藏家与动态、持有人的护照  |
| `ui`                                                      | 当前页面、筛选、待提交票根、分享选择                |
| `runtime`                                                 | 计时器、弹窗状态、翻页与轮播实例等临时对象          |
| `dom`、`assets`、`media`                                  | 挂载点、章面插画的资源地址、票根图片的地址          |
| `domain`、`selectors`                                     | 纯规则，以及对当前数据的查询                        |
| `screens`                                                 | 页面表：某个页面是否存在、讲的是什么、标题与内容    |
| `navigation`、`claims`、`memories`、`social`、`discovery` | 交互控制器                                          |
| `dialogs`、`views`、`render`                              | 弹窗、页面函数与渲染调度                            |
| `sharing`、`images`、`feedback`、`ceremony`               | 导出、图片工具、反馈与领取仪式                      |

`ui` 里随历史记录保存的那部分（页面、筛选、翻到哪一页等）在 `state/state.js` 中单独成组，导航按这一组的字段名保存与恢复；新增这类字段只需写进这一组。

模块工厂只注册函数，数据在注册完成后读取。所有模块动态访问 `appContext.data`、`appContext.catalog` 与 `appContext.community`：它们会被整体替换（加载、每次命令返回、切换首次使用演示），不要在模块初始化时缓存。

`createApp().destroy()` 会解绑事件、取消待提交操作、关闭弹窗并释放对象 URL。Vite 开发热更新可以调用此生命周期方法。

## 后端接口

页面读取的 `appContext.data` 是后端所存内容的副本，只在后端回答之后改变。任何模块都不直接改它，也不直接读写 `localStorage`。

`api` 的全部方法都是异步的，构成接入服务端时需要保持的契约：

| 方法                                               | 作用                                 | 回答                                                 |
| -------------------------------------------------- | ------------------------------------ | ---------------------------------------------------- |
| `loadCatalog()`                                    | 场馆与纪念章                         | `{ venues, stamps }`                                 |
| `loadCommunity()`                                  | 其他收藏家与广场动态                 | `{ collectors, posts }`                              |
| `load()`                                           | 持有人的护照                         | 完整的 `data`                                        |
| `claimStamp({ stampId, method }, { signal })`      | 现场领取                             | `records` `visits` `wanted`，以及 `duplicate`、`day` |
| `recognizeTicket({ file, hint }, { signal })`      | 识别票根                             | `ticket`：编号、场馆、日期                           |
| `redeemTicket({ id, venueId, … }, { signal })`     | 票根入册并领取所选的章               | `records` `visits` `tickets` `wanted`，以及 `claim`  |
| `removeTicket(id)`                                 | 移除票根图片，保留到访与章           | `tickets`                                            |
| `saveMemory(visitKey, { note, photo })`            | 保存感想与照片                       | `visits`                                             |
| `setWanted(venueId, on)`                           | 想去                                 | `wanted`                                             |
| `publishPost({ visitKey, stampIds, note, photo })` | 发布到广场（同一次到访覆盖旧的一条） | `posts`                                              |
| `withdrawPost(visitKey)`                           | 撤回                                 | `posts`                                              |
| `setLiked(postId, on)`                             | 点赞                                 | `liked`                                              |
| `setVisibility({ album, footprints, memories })`   | 公开设置                             | `profile`                                            |

命令的回答形如 `{ data, ...result }`：`data` 只含这次改动涉及的顶层字段，`store.send()` 用它替换 `appContext.data` 中的同名字段，其余原样返回给调用方。命令失败时以带 `code` 的错误拒绝，`data` 保持不变；`store.attempt()` 在此之上统一给出失败提示。领取与识别接受 `AbortSignal`，离开页面时由 `claims.cancel()` 取消，取消的请求不写入任何内容。

以下规则只存在于 `api/local/`，是服务端将要接管的部分：领取日期、收藏编号与发行进度、票根可领哪些章、票根与自定义场馆的标识、领取如何合并为到访，以及其他收藏家持有什么。写入护照的部分（编号、领取合并为到访、规范化与迁移）在 `api/local/passport.js`，演示内容在 `api/local/data/`，票根原图的存储在 `api/local/ticket-media.js`。`domain/` 里只留页面与后端共用的纯规则：到访键、日期校验，以及页面用来预览可领章的 `eligibleStamps`。

`startTrial()`、`endTrial()` 只属于本机实现，供评审侧栏的「体验首次使用」使用：换上一本不保存的空护照，再换回来。

## 数据模型

```text
catalog
├─ venues[]                   场馆：名称、城市、类别、展览、地图位置、照片，以及馆章 stampId
└─ stamps[]                   纪念章：章名、所属场馆 venueId、章面、型号、限量与领取期限

data
├─ records[stampId]            已收藏的章、收藏编号、首次领取日期及到访日期
├─ visits[venueId/date]        到访主体：场馆、日期、票根、徽章、照片、感想
├─ tickets[ticketId]           票根元数据、保存状态及已领取章
├─ wanted[]                   想去的场馆
├─ profile.public             对别人公开的部分：章册、足迹、感想与照片
├─ posts[]                    发布到广场的到访：每次到访一条，保存发布时的感想与照片副本
└─ liked[]                    赞过的广场动态

community
├─ collectors[]               其他收藏家：公开范围、持有的章（stampId、编号、日期、方式）与到访
└─ posts[]                    他们发布的到访：作者、场馆、日期、章与编号、感想、赞数
```

场馆与纪念章是两种对象，各有自己的 id，通过 `venue.stampId` 与 `stamp.venueId` 互相指向；演示数据里馆章与场馆恰好同名，代码不依赖这一点。`domain/catalog.js` 的 `createCatalog()` 提供 `venue(id)`、`stamp(id)`、`venueOf(stamp)`、`stampOf(venue)` 与 `stampsFor(ids)`，查不到时返回 `undefined`，不会用别的场馆顶替。

每个页面的地址带一个 id，它是什么由页面决定（`app/screens.js` 中各页面的 `about`）：场馆页、盖章页、票根页带场馆 id，章页、领取成功页、单章分享页带章 id，到访页带场馆与日期。页面通过 `selectors.venue()` 与 `selectors.stamp()` 取得当前的场馆与章；每种 id 怎样读写、对应哪个场馆与章，见 `app/subjects.js`。

其他收藏家与广场动态由后端以 id 的形式返回；榜单、名次、收藏者名录与广场的信息流仍由 `state/community.js` 在读取时计算。

一条到访可以引用多张票根和多枚章。同一场馆、同一天始终合为一次到访。感想和照片归属于到访，不会因为同馆的另一段参观被覆盖。

`api/local/passport.js` 不依赖 DOM。它负责字段规范化、旧数据迁移、关联校验与合并，只被本机实现调用。本机实现把元数据存入 `localStorage`，票根原图经 `api/local/ticket-media.js` 存入 IndexedDB，原图不会进入 JSON 元数据或网站构建。

第一次读取新版时，可以从旧版键迁移数据。旧版感想归入原参观日期，较早的补录日期保持独立；已经主动清空的新版感想不会被旧备份重新填回。

## 渲染与样式

`views/` 按页面分组，动态个人文本通过统一的 HTML 转义函数（`lib/format.js` 的 `safe`）写入页面。页面画出来之后需要接上的部件（可翻转的徽章、精选轮播、护照册子）写在 `app/render.js` 的一张表里：每种部件一行，写明装在哪个元素上、怎样创建；渲染时先拆掉上一页的，再给新页面里出现的装上，实例按表里的名字放在 `runtime`。增加部件时在这张表里加一行。册子怎样分页、某枚章在第几页这类规则在 `state/selectors.js`，页面只负责画。图标定义保留在 `index.html`，插画通过 ES Module 资源导入交给 Vite 处理。

样式按功能分文件，由 `styles/index.css` 依次导入；后面的文件可以覆盖前面的，所以顺序就是级联关系：

| 文件                                      | 内容                                         |
| ----------------------------------------- | -------------------------------------------- |
| `tokens.css`                              | 颜色、字体等设计变量                         |
| `base.css`                                | 元素的基础样式                               |
| `review.css`                              | 桌面评审侧栏与手机外框                       |
| `shell.css`                               | 页头、主区、页面、页面操作区与底部导航       |
| `components.css`                          | 按钮、空状态、轻提示、弹窗及其表单           |
| `stamps.css`                              | 章面插画、可翻转的徽章、章页与编号           |
| `passport.css`                            | 护照首页的标签与章册卡片                     |
| `claim.css`                               | 现场领取：扫码页、领取成功页与领取仪式       |
| `discovery.css`                           | 搜索、精选、目的地列表与场馆页               |
| `sharing.css`                             | 旅行卡：单章、单次到访，以及足迹与章册的总览 |
| `phone.css`                               | 手机上页面统一的上边距与窄屏留白             |
| `tickets.css`、`memories.css`             | 票根入册；足迹、到访页与记忆                 |
| `passport-book.css`                       | 护照册子：封面、翻页、章页与票根页           |
| `collectors.css`、`map.css`、`square.css` | 收藏家、示意地图、广场                       |

每个文件自带它的窄屏规则（文件末尾的 `@media`）。`phone.css` 是例外：手机上所有页面的上边距与留白会盖过各页面自己写的 `padding`，所以它排在各页面的文件之后，不能并回 `shell.css`。修改颜色与字体从 `tokens.css` 开始，其余在对应功能的文件中调整。

### 配色

界面的颜色全部在 `src/styles/tokens.css` 里命名，其余样式文件只引用名字，不直接写色值。

| 分组 | 变量                                                       | 用途                                                           |
| ---- | ---------------------------------------------------------- | -------------------------------------------------------------- |
| 底色 | `--paper` `--wash` `--soft` `--sunken`                     | 页面与卡片；输入框与空位；分区、胶囊与次级按钮；按下与评审底色 |
| 线   | `--line` `--line-strong` `--idle` `--edge` `--edge-strong` | 分隔线；卡片与控件描边；未选中的页点与开关；虚线空位           |
| 文字 | `--faint` `--subtle` `--muted` `--ink`                     | 编号与提示；说明；辅助正文；正文与标题                         |
| 行动 | `--accent`                                                 | 可以点的、被选中的；现在是护照封面的黑                         |
| 印记 | `--owned` `--want` `--like`                                | 已收藏、想去、赞                                               |
| 其他 | `--danger` `--on-fill` `--shadow`                          | 出错；压在色块上的字与图标；投影的颜色                         |

浅底、描边、光晕、投影等（`--accent-soft`、`--accent-line`、`--accent-ink`、`--owned-soft`、`--veil`、`--scrim`、`--shade-1` 到 `--shade-4` 等）由 `color-mix()` 从上面的颜色算出，写在同一个文件的第二段；换掉 `--accent`，它们跟着变。

可以点的文字用 `--link`，默认就是 `--accent`。主色是黑色时它和正文分不开，所以这类文字另外加重一档字重，并带一个图标或在后面跟一个小箭头（规则在 `components.css` 的 `.button.text` 之后）。主题若想让文字链接有自己的颜色，覆盖 `--link` 一项即可。

物件自己的颜色不在其中，留在各自的样式里：章缘与光晕、奖牌、护照封面与册子的纸张、示例票根、旅行卡（预览与 `controllers/share-card.js` 画出的图片用同一组色值）、地图插画。

加一套主题，是在 `tokens.css` 末尾用同样的名字再写一段，并在 `<html>` 上设置 `data-theme`：

```css
[data-theme='vermilion'] {
  --accent: #b8432f;
}
```

只换主色时写 `--accent` 一项即可；要连中性色一起换（比如暖灰），把底色、线、文字三组一并覆盖。物件的颜色不随主题变化，所以深色主题还需要另行处理册子、票根与旅行卡。

## 构建

网站版使用 Vite 的普通客户端构建，生成带哈希的资源与 `dist/site/index.html`。单文件构建使用同一入口的 IIFE 输出，把代码、CSS 和内联图片嵌入同一份 HTML。

两种构建都从当前源码生成，不依赖历史原型或手工维护的代码拼接清单。`artifacts/` 中的旧版文件只供回看。

## 测试与服务接入

领域规则、本机后端与榜单排名用 Node.js 原生测试运行（`tests/unit/api.test.js` 按上面的契约逐个方法检查），浏览器行为用 Playwright 验证，测试文件按功能划分。按钮与动作、字段、页面表与页面函数、弹窗之间靠名字连接，写错的名字不会报错，所以由 `tests/unit/wiring.test.js` 逐一核对，重名与无人使用的也在其中；`npm run lint` 用 ESLint 检查未使用与未定义的名字。浏览器测试使用隔离上下文及专用端口；`scripts/test-e2e.mjs` 在进程内管理 Vite 测试服务器，运行结束后主动关闭，避免 Windows shell 子进程清理挂起。

接入真实服务时，新写一个与 `createLocalApi()` 返回相同方法的实现（放在 `api/` 下与 `local/` 并列），在 `create-app.js` 的 `api:` 一处换上；演示版与单文件离线版继续使用本机实现。还需要一并处理的有：

- **登录**：目前没有账号。`load()` 就是「当前登录者的护照」，持有人在社区查询里固定写作 `me`；接入时由会话决定身份，未登录的入口需要另行设计。
- **今天**：把 `createClock()` 的固定日期去掉即可使用设备日期；领取日期应以服务端回答的 `day`、`receivedAt` 为准。
- **图片**：票根图片随 `redeemTicket` 的 `file` 上传，页面只通过 `media.url(id)` 取地址，服务端返回地址后改这一处；到访照片目前是压缩后的 data URL，随 `saveMemory` 提交，接入时改为上传后保存地址。场馆照片已是 `venue.photo`、`venue.thumb` 字段。
- **章面**：章的插画与配色仍按 `stamp.art` 对应到样式表里的类名与图集，服务端新增的章需要先在前端补上章面，或改为由数据提供图片地址。
- **社区**：榜单与名录现在由前端对全部收藏家计算，数据量大时应改为服务端的榜单、信息流与名录接口。
- **本机已有数据**：`api/local/passport.js` 的规范化与迁移保留在本机实现里，届时可用来把浏览器中的记录整理后上传。

客户端的文件指纹只能用于当前演示的重复图片提示，不能承担票根真实性验证。
